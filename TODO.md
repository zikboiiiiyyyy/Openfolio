Keep its visual quality, dark editorial art direction, asymmetric hero and case study, project cards, skills, experience, services, contact and footer sections, generated artwork, responsive layouts, sticky navigation, keyboard-accessible mobile menu, skip link, reduced-motion behavior, and component architecture unless a change is necessary to make customization work.

- [x] **Central portfolio configuration and replaceable demo identity.** Create `src/data/portfolio.ts` as the single editable source for the name, professional title, short bio, About copy, optional profile image, location, email, GitHub URL, LinkedIn URL, other social links, skills, technologies, experience, education, projects, services, résumé/CV URL, section/UI copy, navigation labels, SEO settings, favicon, and theme settings. All UI sections must read their content from this configuration; do not hardcode personal information in React components or duplicate editable content in separate modules. Add comments clearly explaining where users edit their information. Replace Ari Vale-specific copy/branding with clearly replaceable examples such as “Your Name,” “Your Professional Title,” and `your@email.com`; do not invent a real person's identity. Keep enough realistic demo content to make the live site complete and visibly mark example experience/projects as examples.

- [x] **Fully data-driven project cards and featured case study.** Each project definition supports name, description, image and alt text, technologies, optional GitHub URL, optional live demo URL, featured status, category, detailed description, features, challenges, and lessons learned. Cards and case-study UI read these fields from configuration, show repository/demo links only when configured, and never invent real metrics. Adding a project requires editing only `src/data/portfolio.ts`; the featured study is selected from project data.

- [x] **Centralize the rest of the portfolio content.** Skills, technologies, services, experience, education, profile/contact/location, social links, and résumé/CV link all live in `src/data/portfolio.ts` and drive their relevant sections. The education section and optional profile-image/CV/social presentation are supported without requiring real personal details. Remove obsolete duplicate data modules after all components use the central configuration.

- [x] **Configurable theme and SEO.** Provide one central way to change primary color, accent color, background, typography, and default light/dark mode; add an accessible working light/dark toggle and preserve the existing dark mode as the default. Make site title, meta description, author, Open Graph image, favicon, and optional keywords configurable from `src/data/portfolio.ts` and apply them to the document.

- [x] **Open-source-ready repository and README.** Include `.gitignore`, `.env.example`, `README.md`, and a standard permissive MIT `LICENSE`; do not include secrets or private information. README includes a project description, screenshots, features, stack, installation, central configuration guide, how to add projects, theme/social customization, environment-variable explanation, development/build commands, and deployment instructions. Include the quick-start sequence: clone repository; install dependencies; edit portfolio configuration; run development server; build for production; deploy. If no external API is needed, add none and document that no environment variables are required.

- [x] **Preserve and verify responsive accessibility and interactions.** Keep mobile, tablet, laptop, and desktop behavior, semantic HTML, keyboard navigation, accessible controls/labels, sufficient contrast in both themes, descriptive image alt text, and visible focus states. Verify navigation anchors, buttons, optional project links, mobile menu, theme toggle, responsive layouts, and that editing central configuration changes visible content.

- [x] **Run, build, and hand off without publishing.** Run the application, strict TypeScript check, and production build; fix TypeScript/build errors; verify the generated `dist/index.html`, route manifest, and README screenshots. Do not publish the website or connect/push to a public GitHub repository without a separate request.
